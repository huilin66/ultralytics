# Multimodal YOLO Paper — Research and Implementation Plan

**状态：** 研究准备阶段；本文档是交给 Codex 执行的工程与实验计划，不代表数据集或方法已验证。

**研究目标：** 基于 Ultralytics 构建可复用、尽量不依赖特定 YOLO 版本的 RGB–Thermal–Depth (RGB-T-D) 多模态二维目标检测框架，研究融合位置、模态可靠性与 Mixture-of-Experts (MoE) 路由对检测精度、鲁棒性及效率的影响。以高质量 SCI 研究论文为目标，但不预先承诺精度提升或期刊分区。

**当前优先级：** Phase 0–2 已完成并通过人工关口；**最终入选数据集为 R-LiViT 与 MID-3K**，下一步进入 Phase 3（Ultralytics 通用多模态基线）。

**最终数据集决策（2026-11-10 人工确认）：** 选用 **R-LiViT、MID-3K**；**InfraParis、MM5、VDT-2048 不进入正式基准**，仅保留 Phase 0 的审计记录、适配器与转换产物以备追溯，不用于训练、消融或论文主表。

---

## A. 科学问题与边界

### A1. 拟研究的问题

- **RQ1（通用性）：** 一个与检测头解耦的多模态模块能否低成本适配多个 Ultralytics YOLO 架构，并稳定优于相同架构的单模态及朴素融合基线？
- **RQ2（融合策略）：** RGB-T、RGB-D、T-D 和 RGB-T-D 的收益如何随场景、目标尺度和融合层级变化？是否存在新增模态导致负迁移的情况？
- **RQ3（MoE）：** 可学习的融合专家与动态路由，相对 Concat/Add/普通门控，是否在公平容量与训练协议下提供稳定收益？
- **RQ4（可靠性）：** 在深度缺失、热图噪声、低照度及模态轻微错位等条件下，可靠性引导的路由是否降低性能退化？
- **RQ5（效率）：** 精度增益是否值得额外 Params、FLOPs、显存和实际推理延迟？

### A2. 研究边界

- 首要任务是**二维边界框目标检测**，不是语义分割、显著性检测、单目标跟踪或三维检测；这些任务的标注不能不加审核地当成常规目标检测 Ground Truth。
- 模态名称固定为 `rgb`、`thermal`、`depth`。不要将 MID-3K 的 `intensity` 与 `thermal` 混淆。
- Depth 可来自原生深度成像或 LiDAR 投影，但须记录来源、单位、有效区域、插值以及参考相机。不得将单目预测深度混称为真实传感器深度。
- 保留原始数据与官方标注不可变；衍生结果均可重建并追溯。
- 不能将不同数据集的 mAP 简单直接平均并声称统一性能；类别空间和评估协议应分别说明。

## C. Phase 1 — 统一数据格式与转换工具

- [x] **状态：** 已完成（五个 Adapter、转换与校验链路已交付）

### C1. 设计原则

统一的是**接口与数据契约**，不是强制把所有模态转成 8-bit RGB，也不是强行把所有数据集映射到同一组类别。使用“共享转换流水线 + 数据集特定 Adapter”：

`raw files → dataset adapter → pairing/calibration → canonical samples → detection labels → validator → statistics/visualization`

转换任务应可重复、幂等、支持 `--dry-run` / `--strict` / `--overwrite`，不覆盖原始数据，记录版本及全部参数。能生成硬链接/软链接时可按环境选择，以减少冗余存储；不能依赖链接才能复现。

### C2. 推荐标准目录

```text
data/
  raw/                         # 原始下载数据（只读；不上传 Git）
    mid3k/ infraparis/ r_livit/ mm5/ vdt2048/
  processed/
    <dataset>/<conversion_version>/
      images/
        rgb/{train,val,test}/<sample_id>.png
        thermal/{train,val,test}/<sample_id>.png
        depth/{train,val,test}/<sample_id>.png
      labels/{train,val,test}/<sample_id>.txt
      calibration/             # 可选，内参/外参/投影配置
      metadata/
        samples.jsonl          # 核心跨模态配对/质量/来源清单
        classes.json          # 数据集原始类→本地类映射
        split_manifest.csv    # sample_id, group_id, split, source
        conversion.json       # 参数、版本、哈希、生成时间
        exclusions.csv        # 排除原因，便于人工审阅
      dataset.yaml            # YOLO 标准类别等元数据；Loader 可根据 manifest 扩展
      quality_report.json
      previews/
```

可改用 PNG/TIFF/NPY 等无损容器存储非 RGB 模态，但要求 `samples.jsonl` 显式写入：`dtype`、`shape`、`units`、`scale`、`invalid_value`、`encoding`、`reference_camera`、`alignment_status` 和 `source_path`。**不要默认所有 depth 都以米保存，也不要对热像逐帧 Min-Max 后覆盖原始辐射数据。**

每组样本共享 `sample_id`，同一份 YOLO 标签仅定义在一个明确的**参考图像坐标系**（优先 RGB；若数据集标注或对齐限制要求以 Thermal 为基准，也要显式记录）。对模态不完全匹配的样本保留错误状态并在配置中决定排除，不进行无提示替换。

`labels/.../<sample_id>.txt` 采用标准 YOLO Detect：`class_id x_center y_center width height`，均归一化到**参考坐标系尺寸**。必须能够与源标注互相追溯。不同数据集使用各自的 `classes.json`，暂不强行跨数据集合并类别。

### C3. 必须实现的适配器及脚本

```text
src/mdet_data/
  schema.py                 # CanonicalSample / Annotation / ModalityInfo
  registry.py               # Adapter 注册与配置
  adapters/
    base.py
    mid3k.py
    infraparis.py
    r_livit.py
    mm5.py
    vdt2048.py
  transform/
    projection.py           # 点云投影、Z-buffer、遮挡/投影合法性
    masks_to_boxes.py       # 实例 Mask→Boxes，类别关联
    normalization.py        # 实验时的数值映射，不破坏 raw
    boxes.py                # 像素框/COCO/YOLO 转换
  validate.py
  stats.py
  preview.py
scripts/data/
  inspect_raw.py
  convert_dataset.py
  validate_dataset.py
  summarize_datasets.py
  generate_previews.py
configs/datasets/<dataset>.yaml
reports/data_inventory/
reports/data_statistics/
```

优先使用 `argparse` 或仓库既有配置机制实现统一命令。每个命令须支持按数据集、split、样本数、输出路径和 seed 配置。不要编写五套互不兼容的脚本。

### C4. 标注转换规则

1. **原生二维检测框：** 优先保留官方类别、官方 split、官方框。完成像素坐标、归一化坐标及投影后的往返校验。
2. **实例分割：** 使用每个实例的独立 Mask 生成最小外接框，并从官方 metadata 获取实例类别；过滤条件（最小可见面积、忽略标签等）配置化，保留被排除对象的日志；目标是可复现的 _derived detection annotations_。
3. **语义分割 / 二值显著性：** 只能生成 _candidate boxes_，**不默认产生可信多类别 GT**。对象相接、遮挡、多个显著对象时需人工抽检/重新标注；缺少类别来源时标记 `annotation_status=candidate_only`。
4. **LiDAR→Depth：** 按真实内外参、坐标系及时间戳，投影至选定的参考相机；实施 Z-buffer，输出深度图、有效像素掩码、覆盖率及匹配置信信息（有据可查才生成）。缺标定/时间同步时 `alignment_status=blocked`，不能直接按分辨率 resize 代替标定。
5. **热像/深度数值：** 原始位深数据保留；训练时预处理作为独立配置和消融因素。显式处理 NaN/Inf、深度 0 值/65535、动态范围及跨数据集不同单位。
6. **几何一致性：** 先核实 RGB、Thermal、Depth 的有效 FOV、对齐与裁剪；所有 Resize/Letterbox/Flip 必须对参考标签与相应模态使用正确、可追溯的几何变换。

### C5. 自动质量检查（转换必须通过）

- 图像/标签可读性，图像长宽/色彩通道/位深，解码失败清单。
- 跨模态 `sample_id` 一一对应，帧/序列/时间戳匹配，缺失率与投影成功率。
- `class_id` 存在性、YOLO 框范围 `[0,1]`、正面积、越界框、重复框、异常小框；所有自动修改可追溯。
- 场景/序列/采集日期重复与跨 split 泄漏（按 group / 序列 / 时间邻近检测）。
- 对齐诊断可视化：RGB-T 叠加、深度伪彩叠加、图像及标签框、投影可见区域；自动选择正常及异常代表样本。
- 标签覆盖度：随机审查*无标签图片是否确实无目标*；只标显著对象的图像不得错误纳入完整检测评估。
- 每个 Adapter 有小规模 fixture 单元测试及逆向坐标验证；完整转换结束生成可机读报告与 warning/error 清单。

**Phase 1 验收：** 至少一个数据集能够完成端到端 `inspect → convert → validate → preview → summary`；其余四个 Adapter 按实际文件结构完成适配（缺文件则明确阻塞），不修改源数据；构建独立 Loader Smoke Test，随机抽查多模态张量与标签同图对应。

### D1. Codex 自动输出统计与可视化

对每个数据集分 Train/Val/Test 和整体输出：

1. 样本数、有效三模态配对数、缺模态/失败对齐数、场景数、序列数、场景独立性及时间覆盖。
2. 原始类别列表、每类实例数、各类出现图像数、长尾分布、忽略类别占比；标注来源：官方框、实例 Mask 衍生框、待审核候选框。
3. 图片分辨率、纵横比、位深与强度分布，深度范围、无效深度比例、LiDAR 投影覆盖率及热像动态范围。
4. Box 长宽、面积、长宽比、每图目标数、COCO Small/Medium/Large（在明确采用的评估尺度下）、目标遮挡/截断信息（若有官方属性）。
5. 训练、验证、测试的类别与场景分布，数据泄漏风险、近重复样本数。
6. 每个数据集至少生成一个随机可视化网格、一个最差质量网格、一个各类稀有样本网格，展示 RGB/T/Depth 和参考框。
7. 估算转换后存储量、训练输入尺寸、基础训练资源需求（只作估算，实测后再更新）。

交付：`dataset_summary.csv`、`class_distribution.csv`、`modality_quality.csv`、`split_leakage_report.csv`、`dataset_selection_report.md`，以及 PNG/HTML 图表。

## E. Phase 3 — Ultralytics 通用多模态基线

- [ ] **状态：** 进行中（E1、E1.5、E3 已完成；E2 的 R-LiViT 矩阵已完成，MID-3K 矩阵未开始）

**结果口径约定：**「**正式训练结果**」= 200 epoch、3 seed、COCO 预训练、完整数据，其 val/test 数值可作为实验结论引用；「**预先测试 / 冒烟**」= 1–3 epoch 或 fraction<1 的短跑，只验证数据/训练/推理链路与显存，其 val mAP 不得作为基线或论文结果引用。

### E1. 工程目标

- [x] **状态：** 已完成（2026-11-10）

- 保留 Ultralytics 作为 Submodule 或锁定依赖，不覆盖上游代码；新功能优先写在独立 Python Package 中。
- 实现统一多模态 `Dataset/DataLoader`、输入 `ModalityAdapter`、插入式 `FusionBlock`、模型工厂与评估入口。
- 保持各 YOLO 检测头/损失/后处理的原生行为，在指定特征层插入跨模态融合；无法复用官方 Trainer 的地方只做最小适配，并给出可复现说明。
- “兼容多个版本”必须由自动构建、前向、反向、训练及推理测试来证明，而非仅靠 model 名称映射。

候选 YOLO：v8、v9、v10、11、12、13（社区版本须单独检查兼容性）、26。**不要假设当前仓库原生支持所有版本；先输出 compatibility matrix。** 先选 1 个版本（建议 YOLO11s 或仓库中最稳定的 s 规模版本）开发，再验证 2–3 个差异较大的版本，最终扩大覆盖。**2026-11-10 人工决定：本实验不纳入 YOLOv13**（当前 Ultralytics 8.4.91 亦未提供其模型配置）。

**两个已知工具问题（影响读数，不影响上面的测量）：**

1. **强形式不成立。** "直接融合显著劣于单模态"没有证据：所有聚合差值都落在 1 个 seed-sd（约 0.005）以内；唯一 p<0.05 的 B4−B0 只有 −0.0088（t≈−1.3），量级不足以支撑"融合有害"的论断。
2. **弱形式成立。** 分场景符号接近对半，增益集中而损失分散：B3 的总增益里前 5 组占 62%，同时 13 组回退 >0.02；**12/40 个序列里单分支 RGB 仍是最优模型**，而 B3/B7 分别多出 35 M/63 M 参数。
3. **增益随模态自身强度走。** corr(B3−B0, B1 组内 mAP) = +0.37：thermal 本身强的序列融合赚钱，thermal 弱的序列融合亏钱 —— 这是"融合继承弱模态"最直接的分场景证据。与类别构成的关系则很弱（corr +0.04；person/car 主导组平均 −0.021，bus/motorcycle/truck 主导组 −0.001），说明驱动因素是成像质量而非类别先验。
4. **三分支 BF 的增益最一致**（17 组 >+0.02、6 组回退、总增益/损失 0.805/0.311），但也只在 p=0.15 水平；增益出现在"第三个模态"，与 E2 的聚合结论一致。
5. **depth 分支目前不存在可测信号。** depth 有效率 1.37–1.62%，40 个测试组之间只差 0.25 个点（median 1.54%），没有可利用的组间变化；B2 depth-only val 0.133。因此 B4≈B0、B5≈B1 的正确解释是"该模态没有信息"，而不是"融合用不好它"，本数据也不能区分这两者。

**对 F2（消融）与 F3（方法）的含义：** MoE 的动机必须写成"跨场景可靠性路由 / 增益不可迁移"，不能写成"融合有害"（后者被数据否定）。F2 的 C1→C4→C6 阶梯正好分离"专家变换"与"可靠性输入"的贡献，C3 容量对照必须保留 —— B3 多 35 M 参数仍在多数序列输给 B0，这条反而说明增益不是容量驱动。在投入 C7 前需要补一个控制：depth 致密化（或论证把 depth 可靠性代理仅用作门控输入而非精度来源），否则 C7（Depth Validity/Quality 特征）没有可验证的信号；若只看精度，方法创新应先在 RGB-T 上成立。

判定规则：

1. **C4 明显 > C3 且 > C2** → 专家变换本身有值，建 C6 才有意义，F3 按"专家 + 可靠性路由"定稿。
2. **C2 ≈ C4 ≈ C3 > C1** → 增益来自"可学习融合权重 / 多余参数"，不是专家结构；F3 的主张必须改写，或止步于 C2，不做 MoE。
3. **四格全 ≈ C1** → 在 R-LiViT 上融合本身没什么可学的（与 F1 的分场景结论一致），方法创新应换数据集或换问题，而不是继续加深结构。

**判定结论（2026-11-16，正式结果对照上面三条规则）：** 规则 1 不成立（C4 不明显高于 C3，也不高于 C2：C4 − C2 = −0.0002 val / −0.0005 test）。规则 2 的前提「C2 ≈ C4 ≈ C3 > C1」同样不成立——三个算子格彼此接近，但**没有一个高于 C1**。事实落点是规则 3 的弱化版：**在 R-LiViT 三模态 BF 上，没有可学习的融合算子优于 concat**；四个格子相对 C1 的 val 差（−0.0044…−0.0084）方向一致地不利，test 上唯一为正的是纯容量对照 C3 的 +0.0017（2/3 seed），属于噪声量级。据此：

- **C6–C9 不建**：没有证据表明「专家混合 + 可靠性路由」能超过 concat。先建 C6 再验证，等于先射箭再画靶；`[moe, 4, 16]` 与 `[moe, 1, 3]` 已经证明加路由、拆专家都不改变结论，换一个 router 输入不会改变这一点。
- **F3 的 Reliability-Aware MoE 主张作废**（按下节定稿条件），论文的方法创新不能建立在这条线上。
- 可写的增益仍然来自 E2：三模态 BF 相对 RGB 单模态在 test 上是 **+0.0197**（B7 − B0，3/3 seed 正、std 0.0014），那是「多模态输入 + 固定 concat」的收益，不是融合学习的收益。F 阶段之后的方向（换数据集 / 换问题 / 把可靠性估计本身做成贡献而不是只做路由）需要在 G 阶段前重新决策，本计划不预设。

1. **论文的方法创新不能写成"更好的融合算子"。** 结构侧的搜索到此为止，继续加算子是先射箭再画靶。
2. **drop 的价值必须到退化条件下检验。** 它是唯一把"辅助模态在推理时可能缺失"这一事实写进训练的格子；若在 T/D 缺失、加噪、模糊下显著优于 C1，叙事应写成"训练期模态丢弃让固定 concat 在传感器退化下不崩溃"，而不是"新融合结构"——这是当前唯一有实验支撑的方法主张。
3. **推理期退化扫描已完成（见下节）**：在现有 12 个 `best.pt` 上做了单/双模态缺失、噪声、模糊，drop 在 7/7 条件上优于 C1，`td0` 配对差 +0.2461。下一步是用 F2 的四个算子格做同样扫描，确认鲁棒性来自"训练期模态丢弃"而不是某个 seed 或结构副作用。

#### F3 退化实验：传感器失效下的鲁棒性（推理期，2026-11-18；无需重训）

上面 8 个格子里的 7 个（F2 的 gated/conv/MoE/单专家 + F3 的 xatt/prod/sepost）都是"想学出比 concat 更好的融合"的尝试，全部失败。第 8 个 `bf-drop` 不是融合算子，而是**训练期模态丢弃**：它和 C1 的融合结构完全相同（`ModalSplit` → `ModalDrop(p=0.15)`），差别只在训练时以 15% 概率把 thermal/depth 通道整体清零。干净 test 上它不占优（−0.0020，噪声量级），但在辅助模态失效时它的主场立刻显出来。

- **drop 的收益泛化到了训练时没见过的损坏类型**：`ModalDrop` 只做过"整块清零"，却在噪声上同样领先（+0.088/+0.136）—— 训练时被迫让 RGB 通路自给自足，损坏的辅助特征就压不垮它。

#### F4. PMRG_V2（逐像素模态可靠性门控）正式结果（200 epoch × 3 seed；2026-11-20 完成）

F3 退化实验把问题定死成了"训练分布"，但这同时把论文推进一个尴尬位置：方法主张只剩一个增广技巧，审稿人必然反问"为什么不用一个显式判断模态可靠性的结构？"。PMRG_V2 就是这个反问的标准答案形态，来自 MRSN 项目（`/root/huilin/projects/MRSN/PaddleCD/paddleseg/models/cx_uper.py` 的 `PixelModalityReliabilityGateV2`，原用于 RGB+NIR+DSM+HSI 分割）。移植成第 9 个融合算子 `pmrg`，与前面 8 个的区别是**唯一让模态在像素级互相竞争**的一个。

机制（逐项照搬参考实现）：

- `concat` → 1×1 → BN → ReLU → 3×3 DWConv → BN → ReLU → 1×1，输出每个模态一张 logit 图，**在模态维做 softmax**，得到逐像素、和为 1 的可靠性权重 `g_m`（其余 8 个算子都没有跨模态归一化：`gated` 是独立 sigmoid、`xatt` 是 concat 上的逐通道缩放、`moe` 是样本级专家路由）。
- 每个模态按 `f_m · (1 + s_m·(N·g_m − 1)) + α_m·g_m·enh_m(f_m)` 重标定，`s_m`、`α_m` 为逐模态可学习参数（初始 0.25 / 0），`enh_m` 为参考实现的 DWConv+BN 增强支路。
- 结构中心化 `N·g_m − 1` 加 zero-init 末层：初始化时 softmax 均匀 → 中心化项为 0 → **第 0 步与 BF 逐位相等**，和 C2–C8 的不变量一致。
- 容量：x 规模 131.2M（C1 122.0M、xatt 130.0M、sepost 134.0M），落在既有容量档内，不是靠堆参数。

| 格子      | 算子                            | 参数量 | s/epoch | 峰值显存 | 3ep val mAP50-95 | 3ep val mAP50 |
| --------- | ------------------------------- | ------ | ------- | -------- | ---------------- | ------------- |
| pmrg      | 逐像素跨模态可靠性 softmax 门控 | 131.2M | 136.4   | 13.74 GB | 0.2690           | 0.4672        |
| pmrg-drop | 同结构 + `ModalDrop(0.15)`      | 131.2M | 133.3   | 13.73 GB | 0.2643           | 0.4301        |

- 冒烟（2026-11-19，3 epoch、seed 0、全量数据、非正式结果）：两格都写满 `results.csv`、有 `best.pt`、无 NaN/OOM；参照 F2 预先测试的同口径 C1 是 0.2475、C4 MoE 是 0.2710，pmrg 落在同一区间。**3 epoch 排序不外推**，只证明模板、迁移、门控梯度、验证选模全链路可跑。
- 测试：`tests/test_multimodal.py` 新增 `test_pmrg_template_starts_at_bf_and_learns_a_reliability_gate`（初始化等于 BF、逐像素归一、zero-init 末层与零 α 阻断梯度、一步后放行），并把模态丢弃测试参数化为 `(bf, bf-drop)` 与 `(bf-pmrg, bf-pmrg-drop)` 两组；整份 112 项全过。
- 正式训练（2026-11-19 06:35 → 20:49 UTC，墙钟 14.2 h；3×RTX 3090，每卡一个 seed 顺序跑两格）：6/6 run 完成 200 epoch，无 OOM、无早停；每 epoch 123.9–127.3 s（比 F3 的 drop 慢约 8%，门控卷积与 BN 的开销），峰值显存 13.77–13.81 GB。产物 `runs/f4_formal/`，test 评估 `runs/f4_formal/test_eval/`，退化评估 `runs/f4_formal/degradation/`。

| **pmrg**  | 0.4432 / 0.4429 / 0.4467 | 0.4443   | 0.4273 / 0.4400 / 0.4298 | 0.4324    | −0.0125 / +0.0090 / −0.0025（1/3 正） |
| pmrg-drop | 0.4413 / 0.4401 / 0.4455 | 0.4423   | 0.4429 / 0.4299 / 0.4390 | 0.4373    | +0.0032 / −0.0010 / +0.0066（2/3 正） |

- **第 9 次复现同一现象**：pmrg 在 val 上曾领先 concat（训练第 34 epoch 时 +0.0087，3/3 seed 正），到 200 epoch 只剩 +0.0026，test 上直接翻负（−0.0019，1/3 seed 正）。加上 pmrg-drop 的 val 低于 pmrg，说明门控学到的东西在长训练里被冲掉了。
- pmrg-drop 的干净 test 均值 0.4373 是现有 11 个格子里最高的（C1 0.4343、conv 0.4360），但配对 sd ≈ 0.015 与差值同阶，**不能作为结构有效的证据**。

**退化（`tools/eval_degradation.py` 同一协议，3 seed 均值）**

| 条件                        | C1 concat     | drop          | pmrg          | pmrg-drop     |
| --------------------------- | ------------- | ------------- | ------------- | ------------- |
| clean                       | 0.4343        | 0.4324        | 0.4324        | 0.4373        |
| t0 热成像缺失               | 0.3957        | 0.4206        | 0.3938        | 0.4241        |
| d0 深度缺失                 | 0.2993        | 0.4327        | 0.3168        | 0.4352        |
| td0 双缺失                  | 0.1695        | 0.4155        | 0.2083        | 0.4201        |
| tn 热成像噪声               | 0.3170        | 0.4047        | 0.3215        | 0.4102        |
| dn 深度噪声                 | 0.2751        | 0.4114        | 0.2759        | 0.4072        |
| tb 热成像模糊               | 0.4220        | 0.4296        | 0.4250        | 0.4317        |
| **Δ 区间（vs 自身 clean）** | −0.012…−0.265 | −0.028…+0.000 | −0.007…−0.224 | −0.030…−0.002 |

- **pmrg 单独仍然崩**：`d0` −0.1156、`td0` −0.2241，只比 C1 好 0.0175 / 0.0388，`dn` 几乎持平（+0.0008）。门控确实"想"压下失效模态，但压不动。
- **机制解释（本格最有价值的一点）**：PMRG 的重标定是**有界乘性**的 —— `1 + 0.25·(N·g − 1)`，N=3 时每个模态的系数只能落在 [0.5, 1.5]，即最多把失效模态的特征减半、把可靠模态放大 1.5 倍。而 C1 在 `d0` 上掉 0.135 是**表示依赖**级别的事故，不是权重能修的：死掉的特征乘 0.5 仍然是死特征，RGB 通路的表示里本来就没有"深度缺失时该用什么"的信息。**失效不是加权问题，是表示问题**；只有训练分布能造出那个表示，这也解释了 drop 为什么在训练时只见过整块清零、却同样能抗高斯噪声。
- pmrg-drop 与 drop 相比：干净 +0.0049，七个条件里 6 个均值更高（含 clean，+0.0021…+0.0055），但只有 `tn` 是 3/3 seed 一致，其余 2/3，`dn` 反而低 0.0042（1/3）。只能写成"同量级、略占优"，**不足以宣称结构贡献**。
- **预注册判定结算**：① 不成立（pmrg 干净 test 劣于 C1）；② 名义成立但幅度在噪声内（pmrg-drop 在 `d0`/`td0`/`tn` 分别 +0.0025 / +0.0046 / +0.0055，seed 一致率 2/3、2/3、3/3）；③ 的严格版不成立。按事先约定，只能取"门控与丢弃不冲突、或有极小互补"的弱说法，**不能宣称门控本身有效**。
- **净结论有两条**：(a) 第 9 个融合算子同样没在干净精度上超过 concat —— 与 F2/F3 合并后可写成"融合结构搜索在 R-LiViT 上系统性无效"，九个算子、三种机制、同一失败模式；(b) 有界乘性门控在结构上无法修复传感器失效 —— 这条给出了正向设计约束：**任何只重加权特征的机制都不够，必须让 RGB 通路在缺失分布上学到表示**。论文方法主体仍是 drop，pmrg / pmrg-drop 作为"结构轴被穷尽"的对照组（第 9、10 格）进表，不争主方法位置。

### F3. ~~建议的主方法：Reliability-Aware Mixture-of-Fusion-Experts~~（2026-11-16 作废，见下）

- **特征提取：** RGB 分支尽量复用预训练骨干；Thermal 与 Depth 使用可配置的轻量适配分支。共享单个 YOLO Neck/Head。
- **融合专家：** 首选 `RGB-T`、`RGB-D`、`T-D`、`RGB-T-D` 四个轻量专家；所有专家输出相同形状的残差特征。可以加入 RGB Identity/Skip 路径。**这一层在 C4/C6 结果明确前不实现**：C4 先用通用特征专家（4 个瓶颈残差专家 + 特征 router）作为 MoE 下界，若 C4 已 ≈ C3，再把专家换成模态子集只会把变量搅在一起。
- **Router：** 基于多模态特征与可观察的深度质量代理输出专家权重；先 Dense/Soft 路由，之后尝试 Top-2 Sparse，但只有真正跳过未激活专家计算才能声称节省 FLOPs。
- **融合位置：** 先固定 YOLO 的一个中层输出（如 stride 16 对应位置；以实际模型结构为准）测试，之后再尝试多尺度 P3/P4/P5。不要在第一版同时引入复杂对齐、Attention 和多尺度模块。
- **深度可靠性：** 区分有效测量、插值值与缺失区域（若数据能支持）；所有代理特征需记录定义，不能当作真实传感器置信度。

> 定稿条件：F2 第一批（C1–C4）跑完且落入判定规则 1 之后，本节才冻结为论文方法描述；若落入规则 2/3，本节改写或作废。**状态（2026-11-16）：作废。** F2 正式结果落入规则 3 的弱化版（无算子超过 concat），可靠性路由没有可路由的对象；本节保留仅作为「被证伪的设计及其证伪依据」记录。

9. **统计可靠性：** 核心模型、主要数据集 3 seeds 起步；报告均值标准差、逐种子完整分数及配对比较，必要时增加重复。
